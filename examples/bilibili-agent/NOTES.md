## 学到并实际应用的方法

1. 明确验收目标：能获取本条视频、查阅字幕与关键画面、回答内容问题并追溯来源。
2. 用独立运行目录保留证据。此视频获取完整 MP4，字幕共 524 段；概览每 30 秒采样一次，共 37 帧，再补查 15 帧。
3. 不确定时回看：根据 07:55 画面辨认 LifeOS 知识库，根据 15:44、15:57 画面确认 docs 与 logs，保留自动字幕原文，不静默篡改源证据。
4. 原始材料、学习结论、工具执行日志与项目状态各自保存；让后续 Agent 从状态文件继续。
5. 将实际跑通的获取与证据阅读步骤封装为技能，保留 CLI，后续任务仍可选择更合适的获取路径。

## 检索与理解验证

- **为什么不只读字幕？** 本次字幕将 Agent 多次识别成其他词，也将 LifeOS、docs、logs 误识别。查看画面才确认名称与目录。依据：07:55、15:44、15:57 的补查帧。
- **Skill 与 Tools 有什么区别？** 在作者的解释中，Skill 是可复用的执行方法，Tools 提供实际能力；多个工具由流程串联。依据：12:29–13:30。
- **为什么先跑通再封装？** 实际执行可以暴露平台风控、下载链路、字幕质量与证据缺失问题；本次确实遇到 412，随后通过正常浏览器可访问的当前视频信息和 HTTP 分段下载完成获取。这个工程结论来自本次实践。
- **怎样支持跨会话继续？** 保存目标、已完成工作、证据位置、验证结果与下一步。视频 16:42–17:27 展示了明确项目状态的价值；本项目已新增状态文档。

## 限制

这次完成的是字幕通读和分层抽帧审阅，没有逐帧观看全部 18 分钟音视频。抽帧之间可能漏掉短暂动作。未复现作者的健康计划、日历写入、邮件发送或定时回顾；它们不是本次学习目标。本项目的检索目前是本地词项匹配，尚未实现跨视频语义知识库。自动字幕保留识别误差；涉及名称、具体参数和操作细节仍需回看确认。
